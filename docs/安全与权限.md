# 安全与权限

先说结论：**本项目的权限层是第二道门，第一道是 DSH 内核的沙箱，加一个专用的低权限系统用户。** 不要只靠本项目去关住一个能动手的助理。

## 它管什么

「助理想做一件事，让不让做、要不要先问你。」实现是 `hub/packages/hub-plugin`（一个挂进内核的插件）：

- 路径逐段解析真实路径，处理链接、Unicode 归一和大小写，助理出不了自己的文件夹和共享区。
- 密钥、配置、凭据一类位置按词和按目录拒绝。
- 动作分级：直接做并留痕、先发审批卡、永远拒绝。审批卡执行前会再核对一次，内容变了就拒绝。
- 读到的外部内容（网页、文件、别的助理转来的话）当「资料」，不当命令；读过外部内容之后，一部分动作会升级成先问。

## 权限三档

全家共用一个档位（不是每个助理一份），在界面「更多 → 权限」里切换，文件是运行目录里的 `config/permission-mode.json`。

| 档 | 含义 |
| --- | --- |
| `open` 全开（新建的运行目录默认） | 跑命令、读写文件、联网读取、助理之间转活，不再出确认卡；下面「一定会问」的四类仍然出卡。 |
| `ask` 改动前问 | 该留痕的留痕、该出卡的出卡、该拒绝的拒绝。**文件缺失、损坏、读不了时，一律按这一档处理，不会按全开。** |
| `readonly` 只读 | 只许读和回答；写、改名册、会写或会联网的命令都拒绝，原因里写明。 |

## 一定会问（全开也一样）的四类

1. 付款或额外积分：调用会花钱或扣积分的外部工具和付款相关动作。
2. 对外发送或公开发布：`git push`、`scp`/`ssh`、发邮件、带上传或改写方法的 `curl`/`wget`、去创建 pr/issue/release 等。普通的联网读取不出这张卡。
3. 删除，或覆盖没有备份的已有文件，或写到助理工作区和共享区以外。
4. 动线上、改系统、扩大授权、读密钥：`sudo`、`launchctl`、`docker`、`kubectl`、`terraform` 一类，以及线上、deploy、凭据路径字样；新建或修改助理名册也算。

命令判定已经拒绝的东西，全开也不会放宽成确认卡。**一键全停优先于任何档位**：全停标记在时，连全开也拒绝。

## 全开之后内核沙箱仍然挡着

命令只在内核的会话沙箱是 `workspace-write`、且沙箱包装已经装上时才运行；否则全开也拒绝并说明。网络默认整段拒绝，被收成「直接做」的联网读取沿用一条窄缝，仍拒绝本机地址和本机套接字。要放开这一层得改内核自己的设置，不是本项目再存一份；不要为了全开改成 `danger-full-access`，插件看到不是 `workspace-write` 会拒绝所有命令。

## 已知限制（0.2.0-beta，请当真）

- 内核 `0.2.2-rc.1` 没有开放「共享区单次写根」接口，`hub/packages/hub-plugin/shared-grant.mjs` 用了兼容实现；这是已知弱点。
- **全开档下有两处判定偏松**：测试里有 2 条已知失败，涉及「读过外部内容之后命令升级为先问」「用重定向把已登记的外部文件复制进自己目录」。（v0.1.0-beta 里「用脚本语言间接写文件或删文件」那几条已修。）需要更稳时请用 `ask`（改动前问）。
- 模型被网页或文件里的话带偏，我们只能靠「当资料」的约定和上面的分级降低风险，不是保证。
- 守卫逻辑是公开的、会被人研究；原则是守卫不靠保密。
- 演示用的假模型不联网，但仍请只在本机运行。
- 不建议无人值守地面向陌生人使用，尤其是模型小、能动手的工具多的时候。

## 网络怎么放

- 网页服务和后端默认只听 `127.0.0.1`；`HUB_WEB_HOSTS` 只接受明确的 IP，拒绝 `0.0.0.0`。
- 给手机用：放在你信任的私有网络（如点对点组网）里，把那块网卡的 IP 写进 `HUB_WEB_HOSTS`。首次进入要输入一次钥匙（`?key=`），之后靠 cookie。
- **不要**把端口直接映射到公网，也不要在没有额外认证的反向代理后面暴露。
- 钥匙、令牌放 0600 文件，别写进命令行参数、截图或聊天；`.env` 已在 `.gitignore`。
