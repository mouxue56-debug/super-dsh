# 全天候：定时来看，条件触发

 【未确认】

看板放在这台电脑上。别的 agent 不常驻，到点来读一次、更新一次，然后退出。
条件触发也一样：外面的定时器调一次小程序，它判断完就退出，最多在看板上建单，不自己动手做单里的事。

令牌只放环境变量，或权限是 `0600` 的 JSON（字段 `url`、`token`）。不要写进命令参数、聊天、工单和下面的样例。

## 1. 在这台电脑上打开看板

中枢后端默认听本机回环，端口见它的 `PORT`（代码里的默认是 3291）。外部 agent 用的地址是：

```
http://127.0.0.1:3291/board
```

端口改过就换成实际端口。只需要放行 `/board/` 这个前缀。网页里的看板还是从中枢自己的页面进，不把令牌写进网址。

先签发令牌（名字用字母、数字、点、下划线和横线，不要用 `owner`，也不要和名册里的助理重名）：

```
hub-board-admin issue agent-a --scope work
```

要跑条件触发、自己建单，把范围改成 `work+create`。令牌只在签发时出现一次，写进 `0600` 的配置文件：

```
HUB_BOARD_URL=http://127.0.0.1:3291/board
HUB_BOARD_CONFIG=/path/to/hub-board.json
```

接通试一次：

```
hub-board list --assignee agent-a
```

退出码 0 且能看到工单（或空列表）就是通了。退出码 2 是地址或令牌没配好。退出码 3 且标准错误是 `HTTP 401` 或 `HTTP 403`，是令牌或权限不对。

## 2. 三个 agent 怎么定时来看一眼

下面都是样例，给人抄。本目录没有安装、也没有加载任何定时器。

三家都可以用同一份做法：系统定时器拉起一次命令，命令结束进程就退出。macOS 的 launchd 样例在：

- `examples/launchd/hub-board-next.plist`：到点跑 `hub-board next`
- `examples/launchd/board-triggers.plist`：到点跑条件触发

各家自己的一次运行入口（未在本机执行过）：

- Claude Code：`examples/claude-code-定时样例.md`
- Codex：`examples/codex-定时样例.md`
- Grok：`examples/grok-定时样例.md`（远端是否够得着这台机器，没有验证）

`next` 会向身份接口要自己的名字，只领取派给这个名字、状态是 queued、还没人领的最旧一张。
没有可领的单：退出码 5，标准输出是「没有可领的单」。
认证失败：退出码 3，标准错误是 `Request failed (HTTP 401)` 或 `HTTP 403`。不要把退出码 5 当成认证失败。
一键全停时不领：退出码 6，标准输出是「已一键全停，没有领取」。停机目录用 `HUB_PANIC_DIR`（绝对路径），或 `HUB_DATA_DIR` 下面的 `panic`。这两处都没配时，不把「找不到目录」当成已经全停。

`watch` 堵到出现符合条件的单，或超时。可以按派给谁、状态、标签筛。
派给谁不写就用自己；写成别人会直接被拒绝。
标签对的是工单的 `project`。工单如果另有 `tags` 数组，也会认。当前格式没有这个字段。
默认最多等 60 秒，轮询间隔 2 秒，都有上限，避免一个参数把进程挂住。
超时退出码也是 3，输出「超时，没有符合条件的单」。`watch` 只看，不领。

给人看的是文字。加 `--json` 给程序读。

## 3. 从派单到交结果

```
派单方建单（queued，派给这个 agent）
        |
        v
定时器跑 hub-board next
        |  没有单：退出码 5，输出「没有可领的单」
        |  认证失败：退出码 3。全停：退出码 6，不领
        v
领到（progress）
        |
        +-- 有节点：hub-board report <id> --progress "时间：做了什么"
        |
        +-- 做完：hub-board done <id> \
        |         --outcome "成果" --checked "怎么验的" \
        |         --unchecked "没验的" --artifact "产物路径"
        |         也可以沿用 report --file，再 done <id>
        |
        +-- 做不了：hub-board block <id> "要人处理什么" --wait-human
        |
        v
派单方 accept，或 send-back 后退回再改
```

`done` 带上那四项时，命令会先交一份报告再标成待验收。报告开头是「执行者自述」。裸的 `done <id>` 仍是原来的意思：只标待验收，要求前面已经交过报告。`done` 不是验收通过。

报进度的旧命令 `hub-board progress <id> "文字"` 还在，和 `report --progress` 走同一条接口。

## 4. 撤销某个 agent 的令牌

在看板那台机器上：

```
hub-board-admin revoke agent-a
hub-board-admin list
```

撤销后立刻失效，再调用得到退出码 3。同一个名字不能马上再签发，要换一个新名字。怀疑泄露时先撤销再重签。令牌进过聊天，就当成已经泄露。

## 5. 条件触发

程序是 `packages/hub-bff/lib/board-triggers.mjs`。读一份规则，判断这一次，然后退出。只发建单请求，不领单、不交结果、不跑规则里的任何命令。

```
node packages/hub-bff/lib/board-triggers.mjs --rules /path/to/rules.json
```

规则样例：`examples/board-triggers.sample.json`。五种条件：

| 种类 | 什么时候建单 |
| --- | --- |
| unclaimed | 某一类单超过多久还没人领。用 state、project、assignee 表示「哪一类」，时间用 `2h` 或毫秒 |
| blocked | 有单被标成阻断，或在等回答。可以指定某一张的工单号 |
| needs-owner | 工单状态是 waiting-human，并且写了待回答的问题。这就是「缺主人才能给的信息」 |
| daily | 到点。见下面的时区和补跑 |
| new-file | 指定文件夹（当收件夹用）里出现新的普通文件。不进子目录，不跟链接 |

每日规则的时钟：

- 不写 `tz`，或写 `"tz": "UTC"`：仍按 UTC。旧配置保持原来的意思，默认只在那一分钟内建单。
- `"tz": "instance"`：按实例时区。时区来自 `io` 测试注入、环境变量 `HUB_TIMEZONE`，或 `HUB_CONFIG_DIR/hub.yaml`、`HUB_HOME/config/hub.yaml` 里的 `timezone`。读不到时区这一条不建单，也不改回 UTC。
- 补跑是配置。`instance` 默认当天补一次（过了整点、还没跨过当地日期，醒了再跑仍用当天那一个幂等键）。`"catchUp": false` 就只认那一分钟。UTC 规则要补必须写 `"catchUp": true`，默认不补。
- 跨日不补昨天。当地日期变了，昨天没跑过的那一档不会再补。

新文件第一次运行只记住目录里现有的文件，不建单。之后只对新增的名字建单。目录不存在，或目录本身是链接，这一次跳过，不把记忆改成空。状态文件默认写在规则文件旁边，权限 `0600`，不要把它放到被监视的文件夹里。

needs-owner 按「规则的幂等键 + 源工单号」各建一张，目标里写上待回答的原文。源单继续停在 waiting-human，触发器不领、不回答。发起人是这次令牌自己的单，不作为下一次的来源。

一键全停时不建单，也不改新文件的基线（停着的时候新进来的文件，恢复后仍算新的）。判断方式和 `next` 相同。

建单必须带幂等键。每天的键会加上当地或 UTC 的日期，同日再跑、错过整点后重启，都会回到原来那张。派给谁的名单里只要出现 `owner`，或规则文件 `reserved` 里点名的名字，整份规则直接拒绝，一张都不建。规则里不能写命令、执行或冒充身份的字段。

样例只给人抄。不要安装 `examples/launchd/` 里的 plist，也不要在这里加载定时器。

令牌需要 `work+create`。输出默认是人能读的几行；`--json` 给程序。

## 6. 安全边界

- 外部 agent 的 `next` / `watch` 只碰派给自己身份的单。`to` 为空、谁都能领的单，`next` 不领。
- 不能把身份写成主人，也不能在请求体里夹带另一个身份。服务端认的是令牌上的名字，类型是外部。
- 不能改别人已经派走或领走的单。领单、报进度、交结果、标阻断都会被拒绝。
- 触发器不能把单派给 `owner` 去点确认。命令行没有建单子命令。
- 直接调用看板上的领单接口时，`to` 为空的单仍可能被领走。这是原有接口，这次没有改。触发器不走那条路。
