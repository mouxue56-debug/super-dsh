# 适合新手的小任务

每一条都小、独立、有明确的「做对了」标准。动手之前先在 issue 里说一声要领哪一条,免得撞车。
通用要求:`npm test` 要过;不要放任何真实的人、店、设备或地址。

## 一、只写文字(不需要会代码)

### 1. 给一本手册写英文版
- 做什么:选 `defaults/manuals/` 里的一本,在同目录加一份 `SKILL.en.md`(内容对应,frontmatter 的 `name` 不变)。
- 做对了:内容和中文版一一对应;`description` 一句话、80 字以内。
- 参考:`defaults/manuals/use-board/SKILL.md`。

### 2. 校对中文和英文说明
- 做什么:通读 `README.md`、`README.en.md`、`CONTRIBUTING.md`,把读不通、前后矛盾、按文档做会卡住的地方列出来,
  提交修改或开 issue。
- 做对了:你照着「五步」在临时目录里走一遍演练(`scripts/install.sh --target <临时目录> --demo`),每步都对得上。

### 3. 写一个新的示例助理人设
- 做什么:新增 `defaults/personas/<id>.md`(例如「整理」或「翻译」),不超过 900 字,保持通用;
  在 `defaults/bots.example.yaml` 加一行。
- 做对了:`npm test` 里关于名册和人设的测试通过;人设里只用 `{{owner}}`、`{{bot_name}}`、`{{manuals}}` 三个占位。

## 二、改数据和小脚本

### 4. 加一张虚构演示工单
- 做什么:在 `defaults/demo/board/tickets/` 加一张工单,场景仍用「示例园艺小站」。格式见
  `packages/hub-bff/docs/工单格式.md`。
- 做对了:`npm test` 里的演示工单校验通过;工单里没有真实的人或店。

### 5. 让 doctor.sh 多查一项
- 做什么:在 `scripts/doctor.sh` 里加一项只读检查(例如运行目录所在磁盘剩余空间),输出「通过/警告/失败」。
- 做对了:在 `test/open-source-prep.test.mjs` 里照现有写法加一条测试;脚本仍然不改动任何文件。

### 6. 给 install.sh 的演练输出加一条汇总
- 做什么:演练结束时多打印一行「将新建 N 项、保留 M 项」。
- 做对了:加测试断言这一行;不加 `--apply` 时目标目录里仍然什么都没写。

## 三、小块代码

### 7. 给版本区间判断多写几条测试
- 做什么:`scripts/lib.sh` 里的 `version_in_range` 判断 DSH 版本是否在区间内。多写几条边界用例
  (例如 `0.2.2-rc.0`、`0.2.3`、`0.2.2-rc.10`、带 `v` 前缀),发现不对就修。
- 做对了:新用例都通过,`npm test` 绿。

### 8. 给开源卫生扫描加一条规则
- 做什么:在 `test/publish-scan.test.mjs` 的 `lineRules` 里加一条通用规则(例如常见的访问令牌形状),
  并让它在仓库里零命中。
- 做对了:规则有单元测试,正反例各一;没有新增命中。

## 想做大一点的

- 皮肤或角色包的加载器(先在 issue 里讨论格式,见 `CONTRIBUTING.md` 第二级)。
- 把「接入内核」那一步(README 第 4 步)做成脚本,默认只演练。
