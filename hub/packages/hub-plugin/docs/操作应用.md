# 操作应用（Cua Driver）：调用处接线

 【确认状态待核】 路 34。代码：`tools/cua.mjs`；守门：`cua-gate.mjs`；测试：`test/r28-cua.test.mjs`
（用 `test/cua-fake-mcp-server.mjs` 这个假的 MCP 服务端，不碰真驱动、不碰屏幕）。
默认**不启用**：权限表 `plugin_tools` 不点名 `cua` 就一个工具都不注册。

## 一、做了什么、没做什么

做了：四个插件工具，每次执行前都过守门，留痕，首次碰的应用出确认卡。
没做：真的 MCP 连接。驱动由内核自带的 MCP 客户端挂（见 `ops/cua-install.md`），宿主把「调用一次 run_steps」
的函数递给本模块（`deps.cua.callTool(name, args, {signal})`，返回 MCP 的结果对象）。本模块不起进程、不读驱动。

## 二、工具与级别

| 工具 | 级别 | 做什么 |
|---|---|---|
| `cua_open_work` | L3 | 开「操作应用」工作会话，出确认卡；要在 `cua.allow_bots` 名单里 |
| `cua_close_work` | L1 | 关会话 |
| `cua_run_steps` | L1 | 按步骤执行；守门说「允许」才做，说「先问」就拒并指路到下一个工具 |
| `cua_run_steps_ask` | L3 | 同参数，先出确认卡，主人点头才做；守门说拒绝或停下时点头也不做 |

级别在内核里是静态的，所以「放权免卡、没放权要卡」只能拆成两个工具；两边都再过一遍守门，卡不是放行凭据。

## 三、每次执行的流程（`runSteps`）

1. 已一键全停（标记在，或读不了）→ 不做。没开会话、会话到期、不是这个助理开的 → 不做。
2. 参数先规整成冻结的深拷贝：只放行已知键；拒窗口号（`window_id`）和自带会话；每步只能是
   click、double_click、right_click、set_value、type_text、press_key、hotkey、scroll、drag、move_cursor 之一，
   外加 `wait_for`、`expect`、`timeout_ms`；`kill_app`、剪贴板、脚本、管理类工具一律不经过这里；
   `observe` 只许 `max_elements`、`max_depth`、`include_screenshot`、`query`，并且强制整窗读取（`since: null`），
   免得只看到「变化的行」而漏掉早就在的登录框。**过守门的就是递给驱动的这一份对象。**
3. 读放权配置（每次现读）：坏了、别人可写、未知键，全拒。不存在 = 没有任何放权（全部先问）。
4. 过 `gateToolCall`：「读过外部内容」取会话当前值，不是 `false` 就按读过；窗口文字只用**同一个应用、
   `text_max_age_seconds` 内（默认 120 秒）、上一次整窗读取**的结果，换了应用、过期、做完没读窗口、驱动报过错，
   一律当拿不到，写动作就是先问。
5. 判定：停下 → 结束工作会话并报「交给主人」；拒绝 → 不做；先问 → 直走工具拒并指路，确认版出过卡才往下；允许 → 做。
6. 做之前 `deps.log` 留一条（放权或已批准、规则名、应用与动作摘要）；内核另会按 L1 / L3-approved 记一条。
7. 同一时刻只有一个调用在做（模块内排队）：共享一块屏幕。
8. 做完：有 `observe` 就把结果文字存为这个应用的窗口文字；读的是浏览器、邮件、聊天这类应用（或不知道是什么应用）
   就标「本轮读过外部内容」，此后写动作先问；结果里有停下词（登录、验证码、付款等）或是受保护应用 →
   结束工作会话，返回以「【停下】」开头的话。结果文字由宿主当资料包起来。

## 四、配置

`hub.yaml` 的 `cua` 段（平面 YAML，单行紧凑 JSON；加载器原样透传，本模块自己校验，写错用默认或拒绝）：

| 键 | 默认 | 说明 |
|---|---|---|
| `allow_bots` | 无（谁都不能开） | 可开操作应用会话的助理 id，`"*"` 为全部 |
| `gate_file` | `<HUB_HOME>/config/cua-gate.json` | 放权与守门配置 |
| `work_ttl_minutes` | 30（1–480） | 会话有效时长，到期作废 |
| `text_max_age_seconds` | 120（5–600） | 窗口文字多久算新 |
| `call_timeout_ms` | 90000 | 单次调用超时 |
| `external_apps` | 常见浏览器、邮件、聊天应用 | 观察到这些就标「读过外部内容」；给了就整个替换默认 |

放权文件 `cua-gate.json` 就是 `cua-gate.mjs` 的 `validateConfig` 格式：
`{"grants":[{"assistant":"<助理id>","app":"<应用名>","until":"YYYY-MM-DD"}],"protectedApps":[…],"stopWords":[…]}`。
放权由主人手工加；本模块不写这个文件，助理的文件工具也写不到配置目录。「点头后以后都允许」这条落盘通道
还没有（见接线说明第 4 点）。

## 五、宿主要接的四处（本轮没动 `index.mjs`）

1. `pluginDeps(...)` 里加 `cua: config.cuaClient`（宿主注入，形如 `{callTool(name, args, {signal})}`，内部转给内核
   MCP 客户端的 `run_steps`）。没注入时开会话和执行都拒。
2. **遮住内核的 `mcp__cua__*`**：工具清单比对会把没登记的可见工具判成「多出」并停掉全部插件工具
   （测试「接线要求」固定了这个行为）。所以内核的 MCP 工具必须先被 `ctx.tools.restrict` 遮掉，再让清单比对跑。
3. **可见性**：`tools/cua.mjs` 导出 `VISIBLE_TOOLS`：没开会话时 0 个；放权助理平时 1 个（`cua_open_work`）；
   开了会话后 3 个。内核是否支持按会话增减可见工具（`tools/change`）我没验证；不支持时退路是：只对
   `allow_bots` 里的助理让这四个工具可见，其余助理 0 个。
4. 之后再做：把确认卡的「以后这个应用都允许，到某天」接到审批链路并写 `cua-gate.json`（要走 L4 保护）。

安装片段与上线后第一次实机验证见 `ops/cua-install.md`。
