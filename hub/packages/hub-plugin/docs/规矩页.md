# 规矩页：主人口头说的规矩，助理记下来、下次带上

  路 14。代码：`tools/rules.mjs`；测试：`test/rules.test.mjs`。

## 一、这是什么

主人会口头跟助理说「以后这类活怎么办、派给谁」。助理用 `rule_note` 记进自己目录的 `规矩.md`；
要全家都照办的，用 `rule_propose_shared` 提议，主人在确认卡上点头才写进共用的派活规则。
下次开工，助理靠 `rules_read` 把两处规矩读回来（见第四节）。

| 工具 | 级别 | 做什么 |
|---|---|---|
| `rule_note` | L1 | 追加一行到自己的 `规矩.md`；只能写自己的 |
| `rule_propose_shared` | L3 | 出确认卡（前后对比），点头才追加到共用派活规则 |
| `rules_read` | L0 | 读自己的规矩页和共用的派活规则 |

格式固定，一行一条，晚会纪要那边在用同一格式：

```
- 2026-11-17 长稿派给小文「以后长稿都交给小文」
```

`- 日期 内容「主人原话」`。原话逐字照抄，用直角引号括起；内容和原话里的直角引号会被换成『』，免得拆坏格式。

## 二、护栏（都有测试）

1. 只许追加自己的：`rule_note` 没有「谁的页」这个参数，身份取宿主给的 `call.bot`，且必须符合名册 id 的写法；
   目录、规矩页是软链接或越界一律拒（`O_NOFOLLOW`、逐段 realpath）。
2. 标签只能由宿主加：内容和原话里凡是方括号标签里带「要求、确认、授权、批准、待核、主人、AI」等字的，
   一律剥掉（含全角括号、嵌套写法、零宽字符拆开写法），并在回复里告诉助理剥了几处。
   不带这些字的普通方括号（如「【附录A】」）原样保留。`rules_read` 读出来时同样再剥一遍。
3. 本轮读过外部内容就不许记：读 `call.readExternal` 与 `deps.state(会话).readExternal`，
   任一为真、或会话不认识，一律拒并告诉助理「请主人在没读外部内容的新一轮里亲口再说一遍」。
4. 上限：规矩页 40 行（暂定，`rules.max_lines`）。到了就拒绝追加并提示「请主人整理」，**不自动删**。
5. 共用规则要出确认卡：卡上 `preview` 就是将要写入的整行原文（由同一个函数生成，整行超过 190 字
   （暂定，`rules.shared_line_max_chars`）直接拒，保证卡装得下）；`why` 写「前 N 条 → 后 N+1 条」和提议理由。
   没点头一个字不写；点头后再检查一次条数上限、重复。重复的不重复追加。
6. 并发：同一文件的「读、检查上限、追加」在进程内排队，10 个并发只写够上限。
7. 文件小：规矩文件必须是普通文件、不超过 64KB。格式不对的行不算规矩（不读出、不进叠加文件），只报「N 行忽略」。

### 已知的软处（如实写）

- **助理自己的文件工具和命令工具也能写它自己目录里的 `规矩.md`**（权限表里自己目录是 L1，只有根
  `AGENTS.md` 例外）。所以上面第 1 到 3 条只管走工具这条路，挡不住助理直接写文件。硬保护要改
  `policy.mjs`（见第五节第 3 条）；命令工具那条路在命令沙箱里仍可写自己目录，这一点改不了，只能靠读出时
  过滤和主人定期看。
- **插件无法核实「quote 真是主人说的」**：它拿不到对话原文。目前靠第 3 条（读过外部内容不许记）和
  原话必填来压住；更严的做法是由宿主在 `call` 里带上本轮主人最后一句话，插件核对 quote 是它的子串（建议，见第六节末条）。
- 确认卡的日期取「出卡时」的当天，执行时若跨过零点，写入的日期会是新的一天；内容不变。

## 三、配置（数字都是暂定）

安装配置 `hub.yaml` 里可以加一段 `rules`（现在 `PASS_SECTIONS` 里还没有它，见接线说明）。不写就全用默认：

| 键 | 默认（暂定） | 含义 |
|---|---|---|
| `max_lines` | 40 | 每位助理规矩页的条数上限 |
| `rule_max_chars` | 200 | 一条内容的字数上限 |
| `quote_max_chars` | 300 | 原话的字数上限 |
| `shared_max_lines` | 40 | 共用派活规则的条数上限 |
| `shared_line_max_chars` | 190 | 共用规则整行字数上限（卡片装得下） |
| `page_file` | `规矩.md` | 自己目录下的规矩页文件名 |
| `shared_file` | `dispatch-rules.md` | `shared/` 下的共用派活规则文件名 |
| `overlay_file` | 空（不生成） | 非空时，每次记完把规矩页生成成这个叠加指令文件，只接受 `*.local.md` |

配置有任何一项不合格，整个模块注册失败（日志里一行错误），宁可没有这三个工具，也不带着坏配置运行。

共用派活规则的实际文件是 `shared/dispatch-rules.md`（已有，由 `defaults/shared/dispatch-rules.md` 种下，
`dispatch-work` 手册第 5 条已指向它）；任务书里说的「`派活规则.md`」就是它，所以本路没有新建模板，原样保留。
工具追加时不碰文件里原有的几行（空模板的那句话不删，主人觉得碍眼可以自己删）。

### 方案 A（叠加文件）和方案 B（开工切片加一行 + `rules_read`）哪种有证据

| | 方案 A：规矩页生成成 `AGENTS.local.md` | 方案 B：开工切片加一行 + `rules_read` |
|---|---|---|
| 做法 | 配 `rules.overlay_file: AGENTS.local.md`；`rule_note` 每次记完用临时文件加改名原子重写它；预设里把 `localInstructionFileCandidates` 从 `[]` 改成 `[AGENTS.local.md]` | 开工切片多一行「你有 N 条规矩，先读（rules_read）」；助理开工先调 `rules_read` |
| 有什么证据 | 内核**静态读包**有证据（上表），**仓库预设目前关着**，没有实例实测 | 代码在本仓库、**本路测试跑过**：`countRules`、`rules_read`、真插件里三工具能注册和执行；开工切片注入已有测试 |
| 好处 | 助理不用记得去读，规矩当指令直接在上下文里 | 不改预设，今天就能用；多占一次工具调用 |
| 风险 | 叠加文件内容被当指令载入，若有人借自己的文件写入工具往规矩页塞话就直接成指令（见第二节软处，需先把这两个文件名加进写保护）；改预设要重新装配置 | 助理可能不照做先读；靠开工那一行提醒 |

代码两种都支持：不配 `overlay_file` 就是纯 B。

## 五、接线说明（本路没改任何已有文件；每条都是改哪个文件的哪一处）

1. **打开模块**：权限表 `plugin_tools` 加 `rules`（`policyText` 的 `pluginTools` 选项里加一项）。不加则三个工具不注册。
2. **配置段**（可选）：`hub-config.mjs` 第 23 行 `PASS_SECTIONS` 加 `'rules'`，才能在 `hub.yaml` 里写 `rules` 段；
   不改就只能用默认值。模块自己校验，坏值整个模块不注册。
3. **写保护**（建议，补第二节的洞）：`policy.mjs` 第 112 行 `protectedPaths` 里除了
   `bots/<id>/AGENTS.md`，再加 `bots/<id>/规矩.md` 和 `bots/<id>/AGENTS.local.md`，
   第 123 行的原因文字改成「助理根目录的指令文件和规矩页只能经专用工具追加」。
   对应 `policy.test.mjs` 里加两条用例。
4. **开工切片加一行（方案 B）**：
   - `tools/index.mjs` 的 `gatherBootInput` 加一个入参 `rules`（数字），原样放进 `input.rules`；
   - `index.mjs` 第 63 行调用它时传 `rules: enabled.includes('rules') ? countRules(install.hubHome, bot) : 0`
     （`import {countRules} from './tools/rules.mjs'`，不会循环：`rules.mjs` 不 import `index.mjs`）；
   - `boot-slice.mjs` 的 `buildBootSlice` 在「等你批」后面加：
     ```js
     const n = Number(input.rules);
     if (n > 0) {
       lines.push({priority: 60, order: 1.5, text: `你有 ${n} 条规矩，先读（rules_read）`});
     }
     ```
     优先级 60：比「等待的工单」（40 起）高、比「知识库」（70）低，超 7 行时先丢工单行；150 token 上限不受影响。
   - `boot-slice.test.mjs` 加：有规矩时多一行；0 条时不出现；超限时的丢弃顺序。
5. **确认卡提前标出会被拒**：`index.mjs` 的 `pluginCard(exec, args)` 把
   `entry?.approvalCard?.(args)` 改成
   `entry?.approvalCard?.(args, {readExternal: Boolean(s.tainted || s.readOutside)})`（`s` 取 `context(exec).s`）。
   本模块已经接受第二个参数（没有就当没传）：读过外部内容的会话发起的提议，卡上会写「本轮读过外部内容，会被拒」，
   不会让主人点了头才发现被拒。
6. **方案 A 才需要**：预设 `packages/devinst/presets-r26.patch.yml` 的 `agent-instructions` 段共 7 处
   `localInstructionFileCandidates: []` 改成 `[AGENTS.local.md]`（`presets-r23`、`r24` 是旧轮，不用改）；
   `hub.yaml` 加 `rules: {"overlay_file": "AGENTS.local.md"}`；先做第 3 条写保护。改完要在实例上验：
   新开会话第一步上下文里能看到「主人口头说过的规矩」那一段。
7. **手册一句话**（`defaults/manuals/dispatch-work/SKILL.md`，已有文件，本路不动）第 5 条后加：
   「主人当场说的规矩，用 rule_note 记，原话逐字；要全家照办的用 rule_propose_shared；开工先 rules_read。」
8. **晚会纪要**：纪要那边读规矩页时按同一正则取行（`- YYYY-MM-DD 内容「原话」`）；可直接
   `import {parseRuleLines} from '../tools/rules.mjs'`。
