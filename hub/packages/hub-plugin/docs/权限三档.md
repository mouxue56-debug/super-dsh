# 权限三档

公开版新装默认全开，四类确认固定开启。改自己、二次确认、任务内授权和上线配置见 [助理改自己](../../hub-bff/docs/改自己.md)。

全家共用一个档位，不是每个助理一份。文件在运行目录的 `config/permission-mode.json`。
正文只能是紧凑的一行：`{"v":1,"mode":"open"}`、`{"v":1,"mode":"ask"}` 或 `{"v":1,"mode":"readonly"}`，末尾可以有一个换行。

插件每次还没被拒绝的判定都会现读这个文件。下面这些情况一律按「改动前问」（`ask`），不会按全开：

- 文件不存在
- 读不了、是符号链接、超过 4096 字节
- 不是上面那一行（多了键、换了顺序、模式写错、不是 JSON）

读取和启动都不会补写这个文件。已有实例缺档、坏档，仍按「改动前问」，不会自动改成全开。

全新运行目录不一样。`scripts/install.sh --apply` 和 `scripts/demo-prepare.mjs`
只在第一次初始化配置时写入全开，权限 0600。
判定是：还没有演示标记，配置目录不存在或是空的普通目录，并且运行根里还没有
助理目录、数据目录、会话或工单（脚本刚建的空脚手架不算）。
这些痕迹已经在的实例，缺档或坏档都不补、不改。读不了或拿不准，按已有实例，不写全开。
再跑一次准备，也不覆盖已经写下的档，包括只读。

一键全停优先于任何档位。全停标记在时，全开也是拒绝，原因是「已一键全停，需先恢复」。

## 三档

`ask` 是现在的行为：该留痕的留痕，该出卡的出卡，该拒绝的拒绝。档位模块对这种判定原样返回。

`open` 全开：跑命令、读写文件、联网读取、助理之间转活，不再出确认卡。下面四类仍然出卡。主人亲自交代的危险操作转确认，其他来源沿用原有权限。

`readonly` 只读：只许读和回答。写、改名册、跑会写或会联网的命令，都拒绝，原因里写明是写、是执行，还是联网。纯查看命令（命令判定标成直接跑、且没有写入、没有联网）可以过。

## 派分身

工具名 `subagent`（本体进程内的分身，spawn 或 fork 都用这一个名字）。权限表登记了 `kernel_tools: ["subagent"]` 之后，派这个动作本身在全开、改动前问、只读三档都不出确认卡。只读档下，分身随后的写和执行仍拒绝。分身不能再派分身，也不能改工作目录或换预设。分身后来的工具调用走和派它的助理相同的判定；全开仍要出卡的四类照旧。确认卡上写「某某的分身想……」。怎么把本体包挂上，见 `packages/devinst/subagent.patch.yml`，那里只是样例，不改正在用的 profile。

## 全开仍要出卡的四类

识别在档位模块里，尽量沿用命令判定已经给出的程序名和原因；命令判定没标出来的，再用下面的词补上。

1. 付款或额外积分：`codex`、`grok`、`opencode`，以及付款、支付、充值、扣费、收银台、积分，
   还有 payment、checkout、stripe、billing。
2. 对外发送或公开发布：`git push`，`scp`、`ssh`、`sendmail`、`mail` 一类，
   `curl`/`wget` 带上传或改写方法（`-X POST`、`-d`、`-F`、`-T`），
   带冒号的 `rsync`，以及 `gh` 去创建或评论 pr、issue、release、gist。
   普通的联网读取不出这张卡。
3. 删除、批量抹除，或覆盖敏感配置和数据：
   `rm`、`rmdir`、`unlink`、`shred`、`srm`、`trash`，`find -delete`，
   `git clean` / `git rm`，`rsync --delete`。
   目录外的普通文件读写不因位置而出卡。
4. 动线上、改系统、扩大授权：`sudo`、`launchctl`、`defaults`、`docker`、
   `kubectl`、`terraform` 等，以及线上、deploy、凭据路径字样。
   新建或修改助理名册也算这一类。

特别危险的操作第二步列出对象和数量。外部资料后的危险操作加一次确认。凭据值、主线 3081 及外部身份各自的归属边界继续保护。

全开仍需可用的命令沙箱。普通本地命令无需确认；识别为读取的命令可以联网。脚本的任意网络副作用无法从命令名判断，
因此通用脚本执行默认没有网络权限，对外发送和付费走已确认的入口。改正在运行的服务使用确认后重启的配置命令。

## 设置接口

- `GET /settings/` 返回档位、各助理的模型和思考强度、模型清单。
  `mode` 只是 `open`、`ask`、`readonly`。没有档位文件时，读到的是 `ask`。
- `PUT /settings/permission` 的正文只能是 `{"mode":"..."}` 这一个字段。
  需要主人网页设备通过登录和同源检查，代理签名由 BFF 校验。
  助理工具、讨论组路径、工单正文都进不了这个写入口。
- `PUT /settings/bots/<助理号>`：不写任何文件，返回 409，错误是 `settings-model-readonly`。

模型和思考强度卡在内核自己的设置上，所以不另存一份：

- `agentPresets/read` 的说明是只供查看，返回预设正文，没有对应的按预设写回接口。
- 本仓库带的预设里没有 agent-loop 那种 `provider` / `model` / `reasoningEffort` 字段。
- `session/selectModel` 只改一个会话，不是这位助理以后都用。
- `agentDefaultModel.saveSelection` 是以后新建会话的全局默认，不是按助理。
- 连上内核要读令牌。本任务不读令牌，设置接口也不发起这种调用。

因此 `GET /settings/` 里每个助理都是 `{model:null, effort:null}`，`models` 是空数组。只有测试或宿主额外注入读取函数时，才会从预设正文里解析这两项，生产路径不注入。

## 拿不准时的保守选择

- 已有实例缺档按改动前问。读取时不写成全开。只有全新实例的初始化会写成全开。
- 插件工具里本来要确认的，全开也不自动放行。
- 只读档里，联网读取也拒绝。
- `docker`、`codex` 这一类名字一律出卡，可能比主人想要的更宽。
- 命令文本里出现「付款」「rm」等词就出卡；文件内容里出现这些词，不因此出卡。
- 认不出是不是覆盖、也没有写路径的命令，不单凭「可能有副作用」出卡。
