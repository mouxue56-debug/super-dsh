# 助理改自己

公开版和自用版默认全开。助理可按主人交代直接改源码、检查、打包。
花钱、对外发送或发布、删除、上线或动线上服务，均需主人在界面上确认。
下列会话结束、健康判据和目录采纳方式是本轮实现选择 。

## 本机 Harness 的依据

安装包 `/Applications/DeepSeek Harness.app/Contents/Resources/` 的 CLI 版本为 `0.2.2-rc.1`。
`dsh web --dump-default-config` 的出厂 `approval` 与 `permission` 块显示，
`danger-full-access` 搭配 `approval: never`，`DSH_PERMISSION_MODE` 可选该模式。
`dsh web --dump-config-schema` 的 `config28.presets` 说明它有完整文件访问权限，无审批提示。
`dsh headless --help` 分别列出 `--permission-mode` 与 `--approval-policy ask|never`，
后者可覆盖所选预设。

安装包 `app.asar` 中的 `dsh-permission-presets/lib/index.js` 注册了这组值。
`dsh-fs-sandbox/lib/index.js` 的 full-access 分支直接返回原目标，
`dsh-bash-sandbox/lib/index.js` 的同名分支直接执行。操作系统和目标服务自己的边界仍有效。
`web --help` 成功。已装的某个可选 bundle 与此 CLI 版本不相容，`tui` 模板不存在。
结论来自出厂配置、schema 和本机实现，未向模型发起任务。

| `tool-levels.yaml`、`hub-plugin/command-policy.mjs` | 白名单、程序拒绝表、`cmd_deny_paths` 锁源码 | 主人回合的普通命令直接做，复用命令解析归类危险操作 |
| `hub-plugin/permission-mode.mjs`、`hub-bff/lib/arrange-model.mjs` | 上轮开关跳过四类 | 四类固定问；花钱、批量删除、群发或改权限等进入两步 |
| `hub-plugin/command-sandbox.mjs` | 旧档限写本目录、限制网络 | 主人回合扩大普通文件范围；保留凭据、主线、运行状态和进程边界 |
| `hub-plugin/index.mjs`、`command-policy.mjs` | 外部资料后审批升级 | 保留；触及四类的确认加一步。其他助理和外部身份权限沿用 |
| `hub-bff/lib/ext/dispatch.mjs` | 历史规则可长期放行外派 | 对外派工仍要主人本次点头 |
| `hub-bff/lib/ext/self-edit.mjs` | 全开可直接重启，手工退回直接执行 | 两个动作各问一次；权限、配置、令牌路径和敏感数据覆盖问两次 |

「改动前问我」和「只读」仍可在设置切换。缺失、损坏的旧档位文件按「改动前问我」处理。
新安装写入全开档；上轮的 `permissions.full_open_like_creator` 不再控制行为。
一键全停、只聊天会话、外部身份看板归属、资料围栏和主线 DSH 边界继续执行。
助手不能读取凭据值。用户数据删除沿用现有软删除能力。

同一张确认卡在今天页和会话中共用。要两步时，第一步展示影响和退路，第二步列出具体对象和数量。
「这一次都同意」仅用于可合并的一步审批，限同一主人回合、同一类、最多 15 分钟，回合结束即失效。
连续点击同一个旧步骤不会触发执行。生产网页代理用设备 cookie 核验身份，再向 BFF 签名。

## 改动、恢复与权限

主人交代 → `self_edit_start` → 写前存还原点 → 改源码 → 检查 → 打包 → 主人点头 → 重启 →
健康检查 → 今天页通知，设置的「改动记录」可退回。

- 同时只维护一次进行中的改动，同一助理和对话内复用。重启获得终态或调用 `self_edit_finish` 后结束。
- 普通 write/edit 命中源码也先存还原点。普通 bash 写源码时工作目录须落在源码内。
  执行期间持有租约，完成后释放，默认最长 660 秒。源码检查和后台恢复均遵守同一改动状态。
- Git 快照纳入原有脏源码，必要时初始化 Git。保存开始前的 HEAD、产物时间和健康结果。
  产物没有单独版本元数据时，HEAD 是开始前版本的参考。构建时间从 `build_artifact` 或 `build_time` 取得。
- 按 `.gitignore`、内建排除表及 `exclude_paths` 排除数据、凭据和 Git 元数据。
  以前已被跟踪的排除文件不进入新快照树，旧 Git 历史和工作区的数据文件保留。
- 检查、打包、重启使用配置的固定 argv。命令输出截断并隐藏常见凭据。
  后台程序可在 BFF 重启后继续监测。默认 30 秒内连续 3 次健康，间隔 1 秒，单次请求限 2 秒。
  变更启动失败时自动恢复源码、打包和重启，按同一健康判据复验。自动恢复是同一次已批准切换的补救。
  健康地址只用本机 BFF。
- 撤销以新提交恢复内容。手动撤销会先给当前版本再存一个保底还原点。
  目标不可用时回到该保底点。记录和还原点仅追加。
- 今天页通知和「改动记录」都可退回。卡上提示重启，主人确认一次后执行。
  主人设备使用 GET `/bff/self-edit/log` 和 POST `/bff/self-edit/restore/:id`。

| 身份与档位 | 读取 | 修改、打包、重启 |
| --- | --- | --- |
| 主人交代的助理回合，全开档 | 可用 | 普通操作直接执行，首次改动存还原点；重启单独问 |
| 改动前问我 | 可用 | 专用工具按本次确认卡执行 |
| 只读 | 可用 | 拒绝 |
| 外部身份、网页和工单材料 | 各自读取范围 | 无法启动改自己 |

## 终端救援

服务停住时使用运行目录独立的 `rescue.mjs`，只需 Node 与 Git。配置为 JSON 值的键值文本。
默认 `$HUB_HOME/runtime/self-edit/rescue.env`，未设置 `HUB_HOME` 时以 `~/dsh-work` 为根。
用真实安装路径和还原点 ID 替换下方示例。

```sh
node /path/to/runtime/self-edit/rescue.mjs --config /path/to/runtime/self-edit/rescue.env list
node /path/to/runtime/self-edit/rescue.mjs --config /path/to/runtime/self-edit/rescue.env restore <id>
node /path/to/runtime/self-edit/rescue.mjs --config /path/to/runtime/self-edit/rescue.env restart
node /path/to/runtime/self-edit/rescue.mjs --config /path/to/runtime/self-edit/rescue.env status
```

## 上线时要动的线上配置

1. 更新首席的 `bots/chief/AGENTS.md`、在用的 `config/bot-template.md` 和助理预设。
   保留名册 `hub:identity` 和 主人 已确认内容，更新原有的外派和目录固定文案。
2. 在现有 `config/tool-levels.yaml` 的 `plugin_tools` 追加 `"self-edit"`，保留其余模块。
   原权限表同时供其他档位和旧全开使用。
3. `config/hub.yaml` 写 `permissions: {"full_open_like_creator":true}`。`self_edit.enabled` 默认关。
   安装接线通过后再开启。每段按平面 YAML 写一行紧凑 JSON，参考 `defaults/hub.example.yaml`。
4. 源码使用实体 Git 根。运行树需要同时包含实际执行的后端和可重打包的壳源码。
   现用两套 Git 仓库时先确定单一运行源码树和打包入口，嵌套 Git 仓库不会被完整备份和恢复。
5. 安装 `packages/hub-bff/ops/rescue.mjs` 和 `rescue.env` 到运行目录的 `self-edit/`。
   首次开始改动也会复制脚本并导出配置。救援配置的 `runtime_dir` 是脚本所在最终目录。
6. 重启命令参照`r38-apply.sh` 的忙闲检查和 `r38-stable-up.sh` 校验产物后原子切换。
   发起重启的回合要能退出，其余在跑的活由重启脚本处理。脚本只管 SDS 本身。
   上线前用隔离环境复验重启、自动恢复，以及网页、BFF 与 Harness 的连通。
7. 给网页和 BFF 的启动环境都配置同一个现有 `HUB_WEB_KEY_FILE` 绝对路径。
   BFF 与网页分开启动时先准备好 0600 文件。BFF 启动时读取，外部接单器无需访问。

| `self_edit` 配置项 | 说明或示例 |
| --- | --- |
| `enabled`、`source_dir` | 默认 `false`，运行源码实体 Git 根如 `/path/to/live-source` |
| `build_command` | `["python3","shell/build.py"]`，从源码根执行 |
| `checks` | 名称到 argv，例如 `{"后端":["node","--test","test/line-length.test.mjs"]}` |
| `restart_command` | 固定 argv，例如 `["/path/to/restart-this-hub"]` |
| `health_url`、`health_key_file` | `http://127.0.0.1:PORT/bff/health` 和本机鉴权文件的路径 |
| `bff_url`、`tool_key_file` | 插件到本机 BFF 的根地址与专用凭据文件路径，权限 0600 |
| `runtime_dir` | 默认运行根下的 `runtime`，程序在这里追加 `self-edit/` |
| `main_dsh_paths`、`exclude_paths` | 主线的真实源码、运行和数据目录，源码内额外排除的相对路径 |
| `build_artifact`、`build_time` | 产物路径或已知构建时间，可选 |
| `health_successes`、`health_timeout_ms` | 默认 3、30000 |
| `health_interval_ms`、`health_request_timeout_ms` | 默认 1000、2000 |
| `timeout_seconds`、`native_lease_ms` | 固定命令默认限 120 秒，原生写入租约默认 660000 毫秒 |

  公开版首次使用默认「改动前问我」，设置里保留用户主动开全开的入口。
