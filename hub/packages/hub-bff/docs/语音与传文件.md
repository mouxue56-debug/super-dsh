# 语音与传文件

决策与验收归 Claude Fable。下面凡是任务书没写死、由本路选定的，都标了  。
（N2）加了 `engine: native` 本体转写，调查结论与配置见文末「本体转写」。

## 现状（动手前查过的）

对话发消息的现成接口只收纯文本：`POST /bff/sessions/:id/messages` 的正文是 `{text, idem}`。
内核客户端 `prompt` 也只送一块 `{type:'text', text}`，没有文件或图片内容块。
网页层说明写着：真实 BFF 只传输入框的纯文本，不上传附件。
已有的 `POST /bff/bots/:id/avatar` 只收头像（约 2MB，几种图片），不是聊天附件。

助理能读文件，靠的是插件里现成的 `read`。会话工作目录就是该助理的目录
（名册给出的 `cwd`，也就是运行目录下的 `bots/<助理>/`）。这里相对路径落在 own 区，`read` 为 L0。
数据目录 `hub-data` 不在这张可读名单里，所以收件不放那儿。

本路用的就是这套现成机制，没有新的内容块，也不调用 `sessions.send`：
文件放进该会话工作目录，返回相对路径。界面把转写文字当作主人的消息发出；
传文件时由界面在那条消息里写上「（附了文件：<名字>，在 <path>）」。助理再用 `read` 打开。

只聊天的会话，插件会拒绝全部工具。本路不绕过。文件仍然可以收下，但那个会话里的助理读不到。
同一个助理的多个会话共用一个工作目录。文件分开放在 `inbox/<会话号>/` 下，
只是为了让消息指向这一份；同助理的 `read` 仍能读到旁边的会话目录。这不是新的权限边界。

## 接口

两个扩展都挂在 BFF 密钥校验之后，文件名就是前缀（`voice.mjs`、`uploads.mjs`）。
加载器按文件名匹配，没有另一张前缀清单。它们不进 `ownAuth`，公开放行阶段匹配不到。
`/uploads/extra`、`/voice/extra` 本扩展不接，交给后面的路由（完整 BFF 上是 404）。

`POST /uploads/`

- 正文是原始字节。查询参数 `conversation`、`bot`。头 `x-filename`。可选 `x-request-id`。
- 成功 200：`{ok:true, id, name, size, mime, path}`。`path` 是相对工作目录的路径，用 `/`，不以 `/` 开头。
- 头里的 `content-type` 若缺了，按扩展名推断；若写了，必须和对得上（别名见下）。`application/octet-stream` 对不上就拒。

`POST /voice/`

- 正文是原始音频。`content-type` 必须是允许的 `audio/*`。查询参数 `conversation`、`bot`，可选 `durationMs`。
- 成功 200：`{ok:true, id, text, durationMs, path, asr:true}`。`path` 是多给界面的，公共约定里没有它。

- 没配引擎：200，`{ok:false, error:'asr-unavailable', asr:false, id, path, durationMs, message}`，音频留下。
- 命令引擎已经落盘的失败（转写失败、超时、配置无效、一键全停）仍是 HTTP 200，`ok:false`，音频留下。
  还没落盘的拒绝用 4xx/5xx。
- 远程 `asr_url` 超时是 HTTP 504，`error` 为 `asr-timeout`。连不上、非 200、跳转、格式不对是 HTTP 502，
  `error` 为 `asr-failed`。这两条的 `message` 都是「转文字暂时不可用，录音已保存」，并带 `retryable:true`、`asr:true`。
  录音留下，回执不是终态。  命令引擎仍用旧字样和 HTTP 200，并且仍是终态。
- 超过 `max_audio_bytes`：413，`error` 为 `audio-too-large`，说明里带字节上限，录音留下，算终态。
  超过 `max_audio_seconds`：400，`error` 为 `audio-too-long`，说明里带秒数上限，录音留下，算终态。
  比 25MB 硬上限还大的正文仍是 413 `too-large`，来不及落盘。
- 空字符串也算转写成功。后端不替主人发。界面若拿空字符串去发消息，现有发消息接口会拒。
- `asr` 是给界面的能力字段：转写已接上为 `true`，没配或两个引擎都配了为 `false`。
  界面靠它去掉「转文字还没接上」。  字段名用 `asr`。

`durationMs` 只回显查询参数里的整数（0 到 24 小时，单位毫秒）。没有就 `null`。不解析音频本身。

别名：`image/jpg`→`image/jpeg`，`audio/x-wav` 与 `audio/wave`→`audio/wav`，
`audio/mp3`→`audio/mpeg`，`audio/x-m4a`→`audio/mp4`。不收视频，默认名单里没有 svg、html、js。

常见报错字样：

| 情况 | error | message |
|---|---|---|
| 会话不存在 | session-not-found | 会话不存在 |
| 超过大小 | too-large | 文件超过大小上限 |
| 类型不许 | type-not-allowed | 文件类型不在允许范围（语音是「音频类型不在允许范围」） |
| 助理与会话不符 | bot-mismatch | 助理与会话不符 |
| 缺查询参数 | bad-query | 缺少会话或助理 |
| 文件名含禁用字样 | bad-name | 文件名含助理不能读的字样 |
| 空文件 / 空音频 | empty | 文件是空的 / 音频是空的 |
| 扩展自己看到未授权 | unauthorized | 需要密钥 |
| 收件目录越出工作目录 | path | 收件目录不在助理可读范围内 |

经完整 BFF 时，缺密钥在扩展之前就被拒，字样是原有的 `BFF key required`。
扩展再挡一层，字样才是「需要密钥」。

## 文件怎么落盘

默认目录名 `inbox`，可在配置里改。相对路径必须落在该会话的工作目录里面。
写成绝对路径、`~/`、`$HOME/`、`$HUB_HOME/` 时会展开，展开后仍必须在这个工作目录内，否则拒绝。
不跟随把目录指到外面的符号链接。文件 0600，新建的目录 0700。不改助理工作目录本身的权限。

文件名：去掉路径，只留最后一段；去掉控制字符、NUL、双向控制符；去掉开头的点；
只留字母、数字、点、下划线和空格、连字符。同名用独占创建，依次为 `名字.ext`、`名字-2.ext`、`名字-3.ext`。
扩展名在盘上改成小写。文件名或会话号若含权限表里的禁用字样（与插件那份名单一致），整次拒绝，
避免交回一条 `read` 会拒的路径。

语音文件名是 `voice-<16位十六进制>.<ext>`。和收件共用同一个会话目录。

`x-request-id` 限定 `[A-Za-z0-9_.:-]{1,80}`，拒绝 `.` 和 `..`。范围是「这个会话 + 这个接口」。
同一个号再来：终态回执原样交回，不另存、不再转。远程转写失败或超时不算终态，同一个号会再用已落盘的那一份去转，不另存。
没给这个头就每次新存一份。处理中的锁超过约 10 秒仍在，返回「请求仍在处理」。

一键全停（`deps.panic.isStopped`，或数据目录里的 `panic/stopped.flag`，判断和现成的 `depsStopped` 一样）：
两个接口都继续收文件。语音不调用转写。都不调用 `sessions.send`。
全停时的回执 `error` 是 `stopped`，并且不算终态：恢复后用同一个请求号再来，会转一次。
`asr-unavailable`、命令转写失败、命令超时、地址形状不对都算终态，同一个请求号不会自动再试。
远程转写超时、失败，以及当时解析到公网或解析失败，不算终态，同一个请求号会再试一次、并再解析一次。
换一个请求号也可以再试。

## 配置

写在安装配置里。插件要认这两段，所以 `packages/hub-plugin/hub-config.mjs` 的 `PASS_SECTIONS` 加了 `voice` 和 `uploads`。
BFF 自己的平面 YAML 读取本来就放行未知段。不写配置时两项都用默认，只是语音没有引擎，调用得到 `asr-unavailable`。

`uploads.dir` 默认 `inbox`。`uploads.max_bytes` 默认 26214400，只接受 1 到这个数，再大视为配置无效。
  暂定上限就停在 25MB，不做到 100MB。
`uploads.types` 是「扩展名 → 类型」的对象，会整表替换默认名单。默认含常见图片、pdf、txt/md/csv、
doc/docx、xls/xlsx、ppt/pptx、mp3/wav/webm/ogg/m4a/aac。webm 只按 `audio/webm`。

`voice.dir` 同样规则。`voice.max_bytes` 同样上限，这是落盘前的硬顶，最大 25MB。
`voice.max_audio_bytes` 不写就等于这个硬顶；写了只接受 1 到硬顶。超过它的录音仍留下，但不再转，并说明字节上限。
比硬顶还大的正文拒在落盘之前。  硬顶仍是 25MB，不把超限的大文件存下来。
`voice.max_audio_seconds` 默认 300，只接受 1 到 86400。查询参数里的时长超过它就留下录音并说明，不解析音频本身。
刚好等于上限仍会转。没给 `durationMs` 就不做这项检查。
`voice.timeout_ms` 默认 30000，只接受 100 到 120000。
`voice.types` 是「audio 类型 → 扩展名」。`voice.asr_model` 只接受字母数字和 `_.:+/-`，最长 80。
没写 `asr_model`、或写成空字符串时，沿用已有的 `model`。`asr_model` 写了但不合法，不会改去用 `model`。
`voice.language` 只在远程地址这条路上使用，形如 `zh` 或 `zh-CN`；不写就不传这个字段。
`voice.asr_url` 与 `voice.asr_cmd` 必须二选一。两个都写是 `asr-misconfigured`，一个都不写是 `asr-unavailable`。都不丢音频。

`asr_url` 原样 POST，不在后面再拼 `/v1/audio/transcriptions`。只允许 `http`/`https`。
允许的地址：回环（`127.0.0.0/8`、`::1`、`localhost`）、私网（`10/8`、`172.16/12`、`192.168/16`、`fc00::/7`）、
`169.254/16`、Tailscale 的 `100.64/10`，以及主机名以 `.ts.net` 结尾。其他一律拒绝，包括公网 IP、
普通域名、带用户名密码、带片段、`http`/`https` 以外的协议。
`localhost` 和 `.ts.net` 在启动时、以及每次请求前都要解析；解析出的每一个地址都必须是上面的私网。
解析不到、或其中有公网地址，启动就拒绝；请求当时才变成这样，则这次不转发，同一个请求号可以再解析。
不把请求改写到解析出来的 IP 上，仍 POST 到配置里的那个地址。
不接受用户名密码。启动时用 HEAD、不跟随跳转看一眼；真有 3xx 就拒绝启动。
连不上或探测超时不拦启动（转写服务可以后开）。  探测超时 3 秒。
请求本身保持 `redirect:'error'`，遇到跳转当成转写失败，不跟过去。
模型名必填。正文是 multipart，字段 `file`、`model`，配了 `language` 再加该字段。
响应 JSON 里要有字符串 `text`；没有 `text` 时接受字符串 `content`。
`text` 若是 `{"content":"..."}` 这种外壳，只取里面的文字。`<|zh|>`、`<|NEUTRAL|>` 这类标签会去掉。
配成公网或会跳转的地址时，后端拒绝启动，原因写在 CONFIGURATION 里。不回显用户名和密码。

`asr_cmd` 是 1 到 32 个字符串，不经 shell。第 1 格必须是绝对路径，不能是占位符。
`{file}` 必须单独占一格，换成音频的绝对路径。`{model}` 同样只能单独占一格，用了就得有模型名。
子进程环境只留 `PATH` 和 `HOME`，避免把本进程里的密钥带进去。超时用 SIGKILL 杀掉进程组。
标准错误丢弃，不写进给界面的文字。

## 上线要加的配置

私网里有了 OpenAI 兼容转写之后，在 hub.yaml 加一行（地址和模型名换成自己的）：

    voice: {"asr_url":"http://<私网地址>:<端口>/v1/audio/transcriptions","asr_model":"<模型名>"}

不配 `asr_url` 也不配 `asr_cmd` 时，行为和配上远程地址之前一样：音频留下，回 `asr-unavailable`。
公网地址会让后端拒绝启动。网页层已经用 `R29_PREFIXES` 转发 `voice`，这一轮没有改那份清单。

## 本体转写（engine: native）

主人的原则（原话）：「Deepseek Harness本身能处理的，就用DeepSeek Harness本身处理。」
只读查清了本体的语音输入：它不是浏览器识别，也不是云端服务，而是随本体安装的本地
sherpa-onnx 原生库 + SenseVoice 小模型（int8 约 239MB）+ Silero VAD，在 CPU 上推理。
`dsh` 命令行没有「转写一个文件」的子命令，界面的识别器也只在插件体系内部；
但后端可以直接复用本体装好的同一套本地资源（证据路径见下）：

- 原生库（真实文件，可直接 require）：
  `.../app.asar.unpacked/dsh/node_modules/sherpa-onnx-darwin-arm64/sherpa-onnx.node`
  （版本 1.13.8，ONNX Runtime 1.28.2）；
- Node 二进制：本体自带 `.../runtime/primary-runtime/dependencies/node/bin/node`；
- 模型：主人已在本体插件页「下载并准备」过，缓存在 `~/.dsh/speech-to-text/sensevoice/models/`，
  大小与 SHA-256 和本体自带的 assets.json 校验值一致（2026-11-09 下载）；
- 官方调用姿势参照本体 `dsh/node_modules/@deepseek-ai/dsh-experimental-speech-to-text-sensevoice/lib/worker.js`。

用法（hub.yaml 一行）：

    voice: {"engine":"native"}

`engine: native` 单独写时，仍与 `asr_url`、`asr_cmd` 互斥：同配算 `asr-misconfigured`（终态，不去转，音频留下）。
`engine` 写成别的非空字符串也一样。不写 `engine` 时完全沿用的 url/cmd 判定。

后端收到录音后落盘，再起一个短命子进程：`<本体node> packages/hub-bff/native/sensevoice-transcribe.cjs <音频>`。
进程无常驻、不下载、不上网；子进程环境只有 `PATH`、`HOME` 和 `DYLD_LIBRARY_PATH`（指到本体原生库目录，
不是用户配置）。stdout 就是转写文字。音频是 16kHz 单声道 16bit WAV 时直读；webm/mp4 等容器先用本机
ffmpeg 转成 PCM（找不到 ffmpeg 时算转写失败）。超时用 `voice.timeout_ms`（默认 30 秒，含模型加载；
本机实测模型加载加一句短话转写不到 1 秒）。

失败与超时和远程引擎同一条路：录音留下，回「转文字暂时不可用，录音已保存」，`retryable:true`、
`asr:true`，HTTP 504/502，不算终态，同一个请求号再来会复用已落盘的那份重转。空输出也算成功。
转写前提是模型已就绪；模型不齐时脚本给出说明并按失败处理（可去本体插件页「下载并准备」）。
原生库或本体不在默认位置时，配置不了路径会一直失败——这是有意的：不新增配置面，等本体修好再说。
  测试可用 `deps.nativeVoice = {bin, script, dylib}` 换成假命令，三个都要求绝对路径。

界面侧不用改：`asr:true` 时壳已不说「转文字还没接上」，失败给重试按钮。

## N8：remote 与合成

`engine: remote` 就是那个私网转写客户端，地址仍写 `asr_url`（原样 POST，不再拼路径）。
要和本体一起用，把顺序写成数组或逗号字符串。前一个超时、连不上或对方报错，才用后一个：

    voice: {"engine":["remote","native"],"asr_url":"http://<私网>/v1/audio/transcriptions"}

`asr_model` 另写。顺序里有 `remote` 就必须有 `asr_url`。
写了地址却没把 `remote` 放进顺序，仍算配置无效。
地址不在私网、模型名不合法，不算「失败」，不会悄悄改走下一档。

合成走 `tts_url`（私网 OpenAI 兼容 `/v1/audio/speech`），另外要 `tts_model`、`tts_voice`。
可选 `tts_timeout_ms`（不写就用 `timeout_ms`，再没有就是 30 秒）。
`tts_max_chars` 不写就是 200，这是单次送给合成的字数。
`POST /voice/speak`，正文 `{"text":"这条回复","id":"消息号"}`。
按句切开，依次合成，返回各段音频的 base64。
念之前去掉围栏代码块、Markdown 表格和链接地址，链接的字留下。
没配 `tts_url` 时回「还没接上」。
  单次默认 200 字、最多念前 16 句。
再长就在回执里标 `truncated`。

## 给适配层 / 集成

本路没有改 `packages/hub-web/server.mjs`。网页层现有 `EXT_PREFIXES` 不含 `voice` 和 `uploads`，
那一项断言也不能由本路去改。适配层需要：

1. 把 `voice` 和 `uploads` 加进转发前缀。
2. 转发头里加上 `x-filename` 和 `x-request-id`。现有白名单没有这两项。
3. 非头像正文上限仍是 512000 字节。25MB 的文件经过网页层会被拒，直连 BFF 可以。适配层要为这两个前缀放宽上限。
4. 语音成功后，由适配层用现有发消息路径把 `text` 当作主人的消息发出。后端不发。
5. 传文件成功后，由适配层在主人的消息里附上「（附了文件：<名字>，在 <path>）」。`path` 是相对该助理工作目录的路径。

直连 BFF 时路径是 `/uploads/` 和 `/voice/`，不是 `/bff/uploads/`。网页层若先去掉 `/bff` 再转发，就能对上。
