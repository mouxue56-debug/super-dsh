# 语音与传文件

决策与验收归 Claude Fable。下面凡是任务书没写死、由本路选定的，都标了  。

## 现状（动手前查过的）

对话发消息的现成接口只收纯文本：`POST /bff/sessions/:id/messages` 的正文是 `{text, idem}`。
内核客户端 `prompt` 也只送一块 `{type:'text', text}`，没有文件或图片内容块。
网页层说明写着：真实 BFF 只传输入框的纯文本，不上传附件。
已有的 `POST /bff/bots/:id/avatar` 只收头像（约 2MB，几种图片），不是聊天附件。

助理能读文件，靠的是插件里现成的 `read`。会话工作目录就是该助理的目录
（名册给出的 `cwd`，也就是运行目录下的 `bots/<助理>/`）。这里相对路径落在 own 区，`read` 为 L0。
数据目录 `hub-data` 不在这张可读名单里，所以收件不放那儿。

本路用的就是这套现成机制，没有新的内容块，也不调用 `sessions.send`：
文件放进该会话工作目录，返回相对路径。界面把转写文字当作主人的消息发出；
传文件时由界面在那条消息里写上「（附了文件：<名字>，在 <path>）」。助理再用 `read` 打开。

只聊天的会话，插件会拒绝全部工具。本路不绕过。文件仍然可以收下，但那个会话里的助理读不到。
同一个助理的多个会话共用一个工作目录。文件分开放在 `inbox/<会话号>/` 下，
只是为了让消息指向这一份；同助理的 `read` 仍能读到旁边的会话目录。这不是新的权限边界。

## 接口

两个扩展都挂在 BFF 密钥校验之后，文件名就是前缀（`voice.mjs`、`uploads.mjs`）。
加载器按文件名匹配，没有另一张前缀清单。它们不进 `ownAuth`，公开放行阶段匹配不到。
`/uploads/extra`、`/voice/extra` 本扩展不接，交给后面的路由（完整 BFF 上是 404）。

`POST /uploads/`

- 正文是原始字节。查询参数 `conversation`、`bot`。头 `x-filename`。可选 `x-request-id`。
- 成功 200：`{ok:true, id, name, size, mime, path}`。`path` 是相对工作目录的路径，用 `/`，不以 `/` 开头。
- 头里的 `content-type` 若缺了，按扩展名推断；若写了，必须和对得上（别名见下）。`application/octet-stream` 对不上就拒。

`POST /voice/`

- 正文是原始音频。`content-type` 必须是允许的 `audio/*`。查询参数 `conversation`、`bot`，可选 `durationMs`。
- 成功 200：`{ok:true, id, text, durationMs, path}`。`path` 是多给界面的，公共约定里没有它。
- 没配引擎：200，`{ok:false, error:'asr-unavailable', id, path, durationMs, message}`，音频留下。
- 已经落盘的失败（转写失败、超时、配置无效、一键全停）也是 HTTP 200，`ok:false`，音频留下。
  还没落盘的拒绝用 4xx/5xx。
- 空字符串也算转写成功。后端不替主人发。界面若拿空字符串去发消息，现有发消息接口会拒。

`durationMs` 只回显查询参数里的整数（0 到 24 小时，单位毫秒）。没有就 `null`。不解析音频本身。

别名：`image/jpg`→`image/jpeg`，`audio/x-wav` 与 `audio/wave`→`audio/wav`，
`audio/mp3`→`audio/mpeg`，`audio/x-m4a`→`audio/mp4`。不收视频，默认名单里没有 svg、html、js。

常见报错字样：

| 情况 | error | message |
|---|---|---|
| 会话不存在 | session-not-found | 会话不存在 |
| 超过大小 | too-large | 文件超过大小上限 |
| 类型不许 | type-not-allowed | 文件类型不在允许范围（语音是「音频类型不在允许范围」） |
| 助理与会话不符 | bot-mismatch | 助理与会话不符 |
| 缺查询参数 | bad-query | 缺少会话或助理 |
| 文件名含禁用字样 | bad-name | 文件名含助理不能读的字样 |
| 空文件 / 空音频 | empty | 文件是空的 / 音频是空的 |
| 扩展自己看到未授权 | unauthorized | 需要密钥 |
| 收件目录越出工作目录 | path | 收件目录不在助理可读范围内 |

经完整 BFF 时，缺密钥在扩展之前就被拒，字样是原有的 `BFF key required`。
扩展再挡一层，字样才是「需要密钥」。

## 文件怎么落盘

默认目录名 `inbox`，可在配置里改。相对路径必须落在该会话的工作目录里面。
写成绝对路径、`~/`、`$HOME/`、`$HUB_HOME/` 时会展开，展开后仍必须在这个工作目录内，否则拒绝。
不跟随把目录指到外面的符号链接。文件 0600，新建的目录 0700。不改助理工作目录本身的权限。

文件名：去掉路径，只留最后一段；去掉控制字符、NUL、双向控制符；去掉开头的点；
只留字母、数字、点、下划线和空格、连字符。同名用独占创建，依次为 `名字.ext`、`名字-2.ext`、`名字-3.ext`。
扩展名在盘上改成小写。文件名或会话号若含权限表里的禁用字样（与插件那份名单一致），整次拒绝，
避免交回一条 `read` 会拒的路径。

语音文件名是 `voice-<16位十六进制>.<ext>`。和收件共用同一个会话目录。

`x-request-id` 限定 `[A-Za-z0-9_.:-]{1,80}`，拒绝 `.` 和 `..`。范围是「这个会话 + 这个接口」。
同一个号再来，哪怕正文不同，也交回第一次的结果，不另存、不再转。
没给这个头就每次新存一份。处理中的锁超过约 10 秒仍在，返回「请求仍在处理」。

一键全停（`deps.panic.isStopped`，或数据目录里的 `panic/stopped.flag`，判断和现成的 `depsStopped` 一样）：
两个接口都继续收文件。语音不调用转写。都不调用 `sessions.send`。
全停时的回执 `error` 是 `stopped`，并且不算终态：恢复后用同一个请求号再来，会转一次。
`asr-unavailable`、转写失败、超时、配置无效都算终态，同一个请求号不会自动再试。换一个请求号可以再试。


## 配置

写在安装配置里。插件要认这两段，所以 `packages/hub-plugin/hub-config.mjs` 的 `PASS_SECTIONS` 加了 `voice` 和 `uploads`。
BFF 自己的平面 YAML 读取本来就放行未知段。不写配置时两项都用默认，只是语音没有引擎，调用得到 `asr-unavailable`。

`uploads.dir` 默认 `inbox`。`uploads.max_bytes` 默认 26214400，只接受 1 到这个数，再大视为配置无效。
  暂定上限就停在 25MB，不做到 100MB。
`uploads.types` 是「扩展名 → 类型」的对象，会整表替换默认名单。默认含常见图片、pdf、txt/md/csv、
doc/docx、xls/xlsx、ppt/pptx、mp3/wav/webm/ogg/m4a/aac。webm 只按 `audio/webm`。

`voice.dir` 同样规则。`voice.max_bytes` 同样上限。`voice.timeout_ms` 默认 30000，只接受 100 到 120000。
`voice.types` 是「audio 类型 → 扩展名」。`voice.asr_model` 只接受字母数字和 `_.:+/-`，最长 80。
`voice.asr_url` 与 `voice.asr_cmd` 必须二选一。两个都写是 `asr-misconfigured`，一个都不写是 `asr-unavailable`。都不丢音频。

`asr_url` 原样 POST，不在后面再拼 `/v1/audio/transcriptions`。只允许 `http`/`https` 的本机回环
（`127.0.0.1`、`localhost`、`::1`），不接受用户名密码和片段，不跟随重定向。
模型名必填。正文是 multipart，字段 `file` 和 `model`。响应 JSON 里要有字符串 `text`。
非回环地址直接 `asr-misconfigured`，不会去连。  公共约束不许连别的机器。

`asr_cmd` 是 1 到 32 个字符串，不经 shell。第 1 格必须是绝对路径，不能是占位符。
`{file}` 必须单独占一格，换成音频的绝对路径。`{model}` 同样只能单独占一格，用了就得有模型名。
子进程环境只留 `PATH` 和 `HOME`，避免把本进程里的密钥带进去。超时用 SIGKILL 杀掉进程组。
标准错误丢弃，不写进给界面的文字。

## 给适配层 / 集成

本路没有改 `packages/hub-web/server.mjs`。网页层现有 `EXT_PREFIXES` 不含 `voice` 和 `uploads`，
那一项断言也不能由本路去改。适配层需要：

1. 把 `voice` 和 `uploads` 加进转发前缀。
2. 转发头里加上 `x-filename` 和 `x-request-id`。现有白名单没有这两项。
3. 非头像正文上限仍是 512000 字节。25MB 的文件经过网页层会被拒，直连 BFF 可以。适配层要为这两个前缀放宽上限。
4. 语音成功后，由适配层用现有发消息路径把 `text` 当作主人的消息发出。后端不发。
5. 传文件成功后，由适配层在主人的消息里附上「（附了文件：<名字>，在 <path>）」。`path` 是相对该助理工作目录的路径。

直连 BFF 时路径是 `/uploads/` 和 `/voice/`，不是 `/bff/uploads/`。网页层若先去掉 `/bff` 再转发，就能对上。
