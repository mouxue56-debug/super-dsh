## 一、固定任务（`lib/routines.mjs`、`lib/ext/routines.mjs`）

一条固定任务 = 哪个助理、什么时候、发什么、怎么算做完、最多做多久。定时只在后端进程内（`setInterval`，
`unref`），不装系统定时、不新增常驻进程。配置写在 `hub.yaml` 的 `routines` 段（单行紧凑 JSON）：

```
routines: {"catchUp":false,"graceMinutes":10,"quiet":{"from":"23:00","to":"06:00"},"items":[
  {"id":"daily-post","name":"日更","assistant":"<助理 id>","at":"07:30","days":"daily",
   "prompt":"写今天的一篇短文","done":"草稿已放到约定目录并在看板回报",
   "escape":{"maxSteps":3,"maxMinutes":30}}]}
```

（实际文件里是一行，这里为排版折行。）

- `prompt`（一句话）与 `playbook`（手册名，发的话是「请按手册「X」办」）二选一。
- `done` 完成条件、`escape.maxSteps` 与 `escape.maxMinutes` 逃生口**必填**，缺了这一条不启用（在
  `GET /routines/` 的 `invalid` 里列出原因）。边界暂定：步数 1–20、分钟 1–240。
- `days` 为 `daily` 或周一=1…周日=7 的数组；`quiet` 可写在条目里也可写在段里当默认。
- 时区：段里 `utcOffsetMinutes`，没有就用 `hub.yaml` 的 `timezone`，再没有用 `deps.utcOffsetMinutes`。

### 运行一次发生什么

1. 到点（目标时刻起 `graceMinutes` 内，暂定 10）：以该助理名义在看板建一张工单（幂等键
   `routine:<id>:<日期>`，同日不会重复）并领单，状态进行中；工单的 `routing.via` 是 `routine`。
   助理不存在或未启用则不建单，记一行 `failed`。
2. 为该助理开一个新会话（`purpose: routine`），发第一句：任务、完成条件、「做完在看板回报」、步数与时间上限。
3. 每个回合结束后看工单：助理已回报、或自己标了阻断/等回答，就收工（成果是**自述**，不自动验收，
   等派单方或主人验）。
4. 没回报：步数没用完就再发一句「继续」；步数用完 → 工单进度写「没做完」并标阻断（`incomplete`）；
   超过最长分钟数（回合没返回也会被计时器截住）→ 标超时（`timeout`）。两种都发通知；
   若 `deps.sessions.cancel` 存在则尝试取消会话（目前内核接口没有，见接线说明）。
5. 每次运行在 `<dataDir>/routines/runs.jsonl` 记一行（`started` 与结尾状态：`reported`、`blocked`、
   `incomplete`、`timeout`、`failed`、`interrupted`、`skipped-quiet`、`skipped-busy`、`skipped-paused`、
   `skipped-duplicate`、`missed`）。

### 其他规则

- 安静时段：到点落在安静时段内就不跑，只记 `skipped-quiet`。手动运行不受安静时段限制（主人亲自点的）。
- 错过：后端当时没在跑。默认不补，只记一行 `missed`（含昨天整天没开后端的那一档）；`catchUp: true`
  才在 `catchUpMinutes`（暂定 240）内补做。
- 暂停：全局或单条，状态落盘（`state.json`），重启后仍暂停；恢复要显式调用。
- 同一条同一时刻只跑一份（`skipped-busy`）。后端重启时，没有结束记录的运行记 `interrupted`，
  工单标「拿不准」交给人。

### 接口（密钥校验之后，不在公开阶段）

`GET /routines/` 列表与今天状态；`GET /routines/runs?limit=`；`POST /routines/<id>/run`；
`POST /routines/<id>/pause|resume`；`POST /routines/pause|resume`（全部）。别的前缀一概不认。

## 二、「今天」（`lib/today.mjs`、`lib/ext/today.mjs`）

`GET /today/`（可带 `?date=YYYY-MM-DD`）返回结构化 JSON，**数字全由代码算好，模型只负责念**。
每一段独立容错，读不到就 `available:false`，不报错、不估算：

- `approvals`：等主人点头的卡（`deps.cards.pending()` 的实时卡 + 晚会待投知识库草稿）；没有 `pending`
  接口时 `cardsSource:"unavailable"`，不装作为零。
- `waiting`：被阻断（含超时、拿不准、失败）、等回答（含问题原文）、等验收的工单，各有计数。
- `yesterdayDone`：昨天完成（被接受）的工单，按助理分组；摘要标 `selfReported:true`。
- `yesterdayUsage`：昨天各助理的调用数、各类 token、金额。金额口径：全有价才「已计价」；一部分没价格
  「部分待定价」（只列有价的部分）；全没有「待定价」；订阅与本地另有标签。**绝不估算。**
- `lastEveningMinutes`：最近一次晚会纪要（往前找 `minutesLookbackDays` 天，暂定 14；超
  `minutesMaxChars` 暂定 6000 截断）。
- `routines`：今天的固定任务及状态。

`hub.yaml` 的 `today` 段可调 `minutesLookbackDays`、`minutesMaxChars`、`itemMaxChars`。
