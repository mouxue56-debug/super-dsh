# 最近删除

对话里的删除都是软删除。墓碑写在数据目录的新文件 `trash.json`，
权限 0600，原子替换，同一进程里的写入排队。
不改内核里的会话，不改会话清单里已有字段的含义，也不改任何已经存在的数据文件。

过期是 30 天。过期以后不再出现在「最近删除」里，也不能再恢复。
墓碑和原来的消息都还在文件里，不会物理删掉。

## 墓碑

三种：

- `message`：一段对话里的一条消息，按消息号或序号。
- `segment`：一整段对话。
- `thread`：一次清空某位助理名下当时的全部聊天段。
  批次里列出这些段的号。之后新来的消息、新开的段不受这批影响。

每条有批次号 `id`、`kind`、`bot`、`session` 或 `sessions`、
消息的 `messageId`、`deletedAt`、`by`（设备）、`label`。
`label` 是给人看的短句，标题会截断，并且只当普通文字。
文件里不存消息正文。

例子：「首席助理 · 1 条消息」「接力『选题』」「和首席助理的全部对话」。

会议、固定任务、组内会话不进这三种删除。
看板卡和工单号也不动。派工、接力的唤醒仍用带 `all` 的会话清单，看得到这些段。

## 接口

都要主人设备：已经通过共享密钥，并且 `x-hub-device` 是 16 位小写十六进制。
没登录、只有助理令牌或外部身份（没有共享密钥）是 401。
有密钥但设备头对不上这个格式，是 403。

扩展挂在 `/trash`。对外路径是 `/bff/trash`
（`server.mjs` 在交给扩展前把 `/bff/trash` 收成 `/trash`）。

- `POST /bff/trash/messages`，请求体 `{session, id}`。删一条。
- `POST /bff/trash/segments`，请求体 `{session, force?}`。删一整段。
- `POST /bff/trash/threads`，请求体 `{bot, force?}`。清空这位助理当前的聊天段。
- `GET /bff/trash`。最近 30 天、还没恢复的，新的在前。
  每条带 `label` 和 `daysLeft`（剩余天数）。
- `POST /bff/trash/<批次号>/restore`。恢复这一批。再调一次也成功，不会改第二次。

正在跑的段，不带 `force` 时返回 409，错误码 `RUNNING`，
话是「它还在做事，先停下？」。`force: true` 才先走现有的取消，再记墓碑。
清空一整条线时，只要其中还有段在跑，同样处理。

重复删同一个对象不会再记一条，返回原来的批次。
恢复后再删，会记新的一批。

错误沿用现有的 400 / 403 / 404 / 409，响应里不带文件路径。

## 删了以后读到什么

- `GET /bff/sessions` 不列出已删的整段。
  只删了其中几条时，这一段还在，但摘要改用还留着的最后一句，不再带被删的那句。
- 未读合计在 `lib/unread.mjs` 的调用处先跳过已删整段，
  再对剩下的消息做 `filterMessages`，然后才交给原来的 `countSessionUnread`。
  那个函数的入参没有改。
- 直接打开已删的整段：`history` 和 `stream` 是 404 `NOT_FOUND`，
  往这段发话也被拒绝。审批卡那条路不动。
- 已删的段如果后来又收到消息（例如派工回复晚到），墓碑还在，不会自动恢复，也不计未读。
- `lib/fulltext.mjs` 只按校验和存确认卡的全文，不索引聊天内容。
  聊天里的搜索靠会话列表摘要和历史；这两处在删除后都不再含被删的正文。

## 给长对话接口

长对话在另一份克隆里做。选「当前段」、拼时间线时用下面这些，不要自己猜：

- `deps.trash.deletedSessionIds()`：这些段不能当当前段，也不能画进时间线。
- `deps.trash.isSegmentDeleted(sessionId)`
- `deps.trash.isMessageDeleted(sessionId, messageId 或 seq)`
- `deps.trash.filterMessages(sessionId, messages)`：整段删了得到空数组。
- `deps.sessions.list()`（不带 `all`）已经去掉隐藏段和已删整段，
  所以「最近一段还能接着说的」不要从 `list({all:true})` 里拿。
- `list({all:true})` 仍包含已删段，唤醒和看板继续用它。

恢复立刻生效：上述函数马上就不再把这段当成已删。
过期的批次仍算已删，只是 `GET /bff/trash` 和 `restore` 不再认它。

长对话读取会排除已删整段，并滤掉已删消息。已删段不能当当前话题，
也不进归类候选。首页的最后一句、未读和话题数按还留着的内容重算。
清空一整条线之后，新开的段不受这批墓碑影响。
合并进某个话题的成员，删这个话题时一并记墓碑（响应里的 `related` 是另外几批的号）。
删其中一个成员只记那一段。撤销合并不会把墓碑揭掉，要恢复得走最近删除。
