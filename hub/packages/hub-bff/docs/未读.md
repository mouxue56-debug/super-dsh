# 未读

个人助理要在会话、助理和讨论组上看到数字（+1、+2），不是红点。
本模块只负责后端计数和已读位置。

## 接口

- `GET /unread/` → `{ok:true, conversations, bots, groups}`
  - `conversations`：单聊会话号 → 未读条数。
    带 `groupId` 的组内工作会话不出现在这里。
  - `bots`：助理号 → 该助理名下单聊未读的合计。
    讨论组的消息不加进这里。
  - `groups`：讨论组号 → 组里未读条数。
- `POST /unread/read`，请求体 `{conversation, upTo}`。
  - `upTo` 省略、`null` 或 `""` 表示读到当前最新一条。
  - 比已经记下的位置更旧时，已读位置不动。
    响应里的 `upTo` 仍是原来那个更远的位置。
  - 对不上任何一条现有消息时返回 400，不改已读位置。
  - 会话号既不是单聊、也不是组内工作会话、也不是讨论组时返回 404。
- 成功时 `upTo` 是实际记下的消息号。
  当时一条消息都没有则为 `null`。
- 讨论组的 `conversation` 填组号。
  组号和某段会话号撞车时，按会话处理，不改组的已读位置。

## 一条未读怎么数

不另存消息。每次现读已有来源，所以刷新、重连、
把同一段历史再投影一次都不会累加。

单聊来自内核历史投影（`client.history`，
规则在 `lib/timeline.mjs` 的 `messageFromEvent`）：

- 只数 `assistant/message` 投影出的助理正文。
  流式增量（`text-delta`）不会变成独立消息，同一序号只留一条。
- 主人自己的 `user/message` 不算。
  `source.kind` 不是 `user` 的系统上下文，投影时已经丢掉。
- 工具步骤不是一条消息。没有对应正文时，投影会造
  `id` 以 `tool:` 开头、正文为空的占位，这两类都不数。
  同一条正文上附带的工具调用仍只算这一条正文。
- 消息没有稳定 `id` 时无法和重放区分，不数。
- 已读锚点若被历史替换弄丢、但还留着序号：只数序号更大的助理正文。
  锚点既不在列表里、又没有序号时，这一段先全部算未读，
  避免把没把握的当成已读。

讨论组来自 `dataDir/groups/<组号>/messages.jsonl`
（现成的 `readMessages`，不复制正文）：

- 只数成员里 `kind === 'assistant'` 的发言。
  主人（`from === 'owner'`）、`system: true` 的样板、
  外部成员、空正文都不数。
- 组消息没有流式分段；同一 `id` 出现多次只算一条。
  带 `toolCalls` 的仍是一条发言，不按工具调用次数拆开。
- 成员表缺失、分不清谁是助理时，退回到
  「不是主人、不是系统样板、有正文」都算。
  宁可多显示，也不把分不清身份的发言漏掉。
  现有组文件都带成员表。

## 已读位置

只落盘锚点，不落盘消息。
文件是 `dataDir/unread-cursors.json`（权限 0600）。
单聊锚点是 `{id, seq}`，讨论组锚点是消息号。

读改在进程内排队。并发两次 `read` 时，
后写完的那次如果更旧，不会覆盖更远的位置。
文件损坏就改名挪走并当成「还没读过」
（未读会重新出现，不会把全部标成已读）。
文件本身读不了（例如被换成符号链接）时接口返回 503，不覆盖原文件。

后端重启后只重新读这个文件。历史仍向内核或组消息文件要。

## 身份

`server.mjs` 的顺序是：先对 `x-hub-bff-key`，
通过才把这个请求标成可信；`/board` 的公开扩展在拒绝之前；
没有密钥则 401，扩展看不到请求。

`unread.mjs` 不在加载器的 `ownAuth` 里，
所以只会在私有阶段被调用。
扩展里再查一次 `deps.isTrusted(request)`，
对不上就 401，不读正文、不写已读位置。
扩展不自己解析密钥，也不接受看板的外部令牌。

## 给接线的人

- 网页层要把 `unread` 加进 `EXT_PREFIXES`，
  浏览器的 `/bff/unread/` 才会转到这里。
  那一行在适配层的 `packages/hub-web/server.mjs`，本路没有改。
- `deps.sessions.history` 是本路在 `server.mjs` 上加的一行，
  指到现成的 `client.history`。
  没有这行时，本接口返回 503，
  不用会话清单上的旧 `unread` 计数顶替
  （那个计数是回合结束加一，对不上「完整消息」）。
- 旧的 `POST /bff/sessions/<id>/read` 仍把清单里的 `unread` 清零，
  和本文件的锚点互不改写。
