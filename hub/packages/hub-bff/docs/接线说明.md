# 接线说明（留给集成轮；本线没有改任何现有主文件）

## 1. 把看板接口挂到现有 HTTP 服务（packages/hub-bff/server.mjs）
- 现状：`createHandler` 里的 `handler`（约第 201 行起）一进来就校验 `x-hub-bff-key`，不通过直接 401。看板接口用自己的令牌，所以必须挂在这道校验**之前**。
- 加法（三处）：
  1. 文件顶部 import：`createBoard` 自 `./lib/board.mjs`，`createBoardHandler` 自 `./lib/board-http.mjs`。
  2. `createHandler` 里 `ticketsDir` 旁边建：`const board = createBoard({root: boardDir, onEvent: ev => runtime.boardEvent?.(ev)})`；`const boardHttp = createBoardHandler({board, configDir})`。`boardDir` 新增一个配置项（例如环境变量 `HUB_BOARD_DIR`，默认放在 `ticketsDir` 同级的新目录，**不要**与旧五栏目录共用）；`configDir` 用现有的 `HUB_CONFIG_DIR`。
  3. `handler` 第一行（鉴权之前）：`if (await boardHttp(request, response)) return;`
- 暴露面：这条路径给外部 agent，经 tailnet 或反代转发时只放 `/board/` 前缀；令牌在 `configDir/board-tokens.json`（0600，用 `bin/hub-board-admin.mjs issue` 签发，默认 read）。
- 事件：`onEvent` 的事件里 `attention:true`（blocked / waiting-human / failed）进「等你」；`notify:true`（completed）进「通知」；`inboxFor` 非空表示进该派单方的收件项；其余不打扰。运行时对应处理由集成轮补。

## 2. 派活资格按名册属性（packages/hub-bff/lib/delegation.mjs、store.mjs、hub-plugin）
- `delegation.mjs` 第 24、48、94 行与 `parseTicket` 里 `creator!=='chief'`、`assignee==='chief'`、`store.get(...).bot==='chief'` 三处按 id 判断首席：改成读名册条目 `canDispatch(roster, name)`（`lib/board.mjs` 已导出；默认能派，`can_dispatch:false` 或 `paused:true` 才不能）。`BOT_IDS` 常量改为从名册取。
- 插件 `delegate_to_bot`：按线 A 的 A2，拆成 `list_bots` 与 `send_to_bot`；内部改为调用 `board.create(actor, {...key})`，`actor={name:<助理名>,type:'assistant'}`，用 `key` 做幂等。接单则 `board.claim/progress/report/done`。
- 派给外部工人（Codex、Grok）：用 `canDispatchExternal(roster, name)`（名册里 `can_dispatch_external:true` 才许），怎么派、派给谁不写进代码，走 `routing` 预留字段与 主人 口述规则。

## 3. 旧工单
- 旧五栏 `.md` 不迁移不改；需要在看板上显示时，读文件后调 `convertLegacyTicket(text, filename)`（只读转换，返回新格式对象，不合规返回 null）。旧 `done` 映射为 `completed`，旧 `running` 映射为 `progress`。

## 4. 转手上限与其他配置
- `createBoard({maxHop})` 默认 4（AI 定的数，做成配置）。令牌范围 `read | work | work+create`。
