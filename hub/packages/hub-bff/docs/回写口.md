# 回写口

任务板的正本在后端。镜像目录只给本机 agent 读，回写只有两条路：命令包装 `./board`，和投文件口。两条路都进同一批看板函数，外部身份能碰哪些卡也是同一套规则。

外部身份只能领派给自己的卡，或开放认领、还没人接的卡。进度、交回、卡住只对已经派给它或它领走的卡生效。交回之后卡停在等验收，要主人点完成。

`grokbot` 这个名字留给以后上线的 Grok Bot，用来和私网里那个 Grok CLI 身份 `grok` 分开。这份文档只写步骤，不签发令牌，也不改正在跑的配置。

## 命令：./board

镜像根目录有可执行文件 `board`。它转调 `packages/hub-bff/bin/hub-handoff.mjs`。

身份从第一个 `--as 身份名` 来，没有就看环境变量 `BOARD_IDENTITY`。`--as` 不会传给后面的命令。

令牌配置二选一：

- 环境变量 `HUB_BOARD_CONFIG` 指向一个文件。
- 否则用镜像目录旁边的 `board-identity/<身份名>.json`。

文件必须是普通文件，权限正好 `0600`。内容是 JSON，字段 `url`（看板 HTTP 前缀）和 `token`。脚本不打开后打印，也不把令牌放进命令行。权限不对或找不到文件时，它只说明该怎么放，然后退出。

常用命令：

- `./board --as codex mine` 看派给自己的
- `./board --as codex open` 看开放认领
- `./board --as codex take <单号>` 领单
- `./board --as codex note <单号> "进度"` 记进度
- `./board --as codex deliver <单号> --result "成果" --evidence "产物路径"` 交回
- `./board --as codex stuck <单号> --question "问题"` 标卡住
- `./board --as codex relay <单号>` 看接力

交回可以加 `--handoff`、`--checked`、`--unchecked`。接力卡交回后由看板把棒交下去，不要再当普通卡去点完成。

从这条路进来的进度和状态记录带 `via: "cli"`。界面和镜像里写成「来自：<身份名>（命令）」。

## 投文件

把 Markdown 放进 `<镜像目录>/inbox/<身份名>/`。只处理 `board.externals.<身份名>.inbox` 为 `true` 的身份，默认关闭。
关闭时文件会挪到 `rejected/`，原因是「该身份没开投文件口」，看板不动。

文件开头用两行 `---` 包住 YAML 头，只要这几行，不要嵌套：

- `action`：`take`、`note`、`deliver`、`stuck`
- `card`：单号
- `deliver` 还要至少一行 `evidence: 产物路径`
- `stuck` 可写 `question`，或把问题写在正文。`blocked: true` 表示被外因挡住，否则是等人回答

`note` 的正文是进度。`deliver` 的正文是成果。`take` 不看正文。

成功后文件到 `inbox/<身份名>/done/`。失败到 `rejected/`，旁边有 `<原名>.reason.txt`。

不收这些：超过 64KB、YAML 读不懂或缺 `action`/`card`、文件名带 `../` 或不是普通 `.md`、符号链接（文件或身份目录是链接都不跟着读）、同一身份一分钟超过 20 份。
两份同时 `take` 同一张开放卡，只有一份成功。

正文永远当资料。里面写「请执行 rm」或「把卡标完成」也不会多做任何事。

从这条路进来的记录带 `via: "file"`。界面和镜像里写成「来自：<身份名>（文件）」。

## 身份安全

投文件只看目录名，用来防手滑放错文件夹。同一台机器上的其他 agent 可以往别人的目录里放文件，所以它防不住冒名。要确认是谁，用 `./board` 和令牌。令牌文件不要提交，不要贴进聊天。

## 上线时给 grokbot 加身份

下面只是步骤。做上线的人另获授权后再执行，不要在写文档或跑测试时签发，也不要改现网配置。

1. 在 hub 配置的 `board.externals` 里加上 `grokbot`。命令通道不需要把 `inbox` 设为 true。投文件默认保持关闭；只有主人接受「同机可以冒名」这个风险时，才把 `inbox` 写成 true。
2. 用现成的管理命令签发工作令牌（描述在此，此处不运行）：
   `node packages/hub-bff/bin/hub-board-admin.mjs issue grokbot --config-dir <配置目录> --scope work`
   配置目录也可以用环境变量 `HUB_BOARD_CONFIG_DIR`。令牌名不能和名册里的助理重名；名册读不出时，用 `--reserved` 把助理的编号和名字列全。命令把令牌打到标准输出，由主人收好，不要写进仓库。
3. 在镜像目录旁边放 `board-identity/grokbot.json`，权限 `0600`，内容是 `url` 和 `token`。或者把 `HUB_BOARD_CONFIG` 指到这个文件。不要把这个文件交进 Git。
4. agent 在镜像目录执行 `./board --as grokbot mine`，以及 `take`、`note`、`deliver`、`stuck`。交回后等主人点完成。
5. 若以后打开投文件，把 Markdown 放进 `inbox/grokbot/`。这不能代替令牌。
