# 助理主动说一句

  主人只在站内看到三种话。不发系统推送、邮件或别的消息。句子由代码按模板拼，不调模型。

## 三种话

- 晨间一句，由名册里 `role` 为 `chief` 的那位说。没有这位，句子仍在，但不安一个名字。
- 有验收并且核验里有一条 `pass` 时，由原接话的助理说一句。派工、领取、处理中不说。
- 工单停在 `waiting-human` 且有待答原文时，由原接话的助理把那句问出来。
  只有发起方是主人（`from.type` 为 `owner`），或顺着上级工单、工单上格式正确的会话号能回到那条线，才进这句主动提醒。
  助理自己建的单再标等主人，不进主动提醒；看板和「今天」详情仍保留。空会话号、坏会话号、链路断了，都不进。

每句带一张来源工单和一个入口。来源会话号能用就指向那段会话，否则只指向工单。

原接话的助理按这个顺序找：来源是助理就用来源，否则用接手人，再否则用指定名单里仍启用的一位。对不上名册就只显示句子。

## 暂定尺度

安装配置 `notices` 段可以覆盖。坏值退回下面的默认，白天上限不能大于 2。

| 项 | 暂定 | 含义 |
|---|---|---|
| `quietStartMin` | 1320 | 22:00 起静默 |
| `quietEndMin` | 480 | 08:00 前仍静默 |
| `morningMin` | 510 | 08:30 试晨句 |
| `morningEndMin` | 720 | 12:00 前晨句才带「早」 |
| `dayCap` | 2 | 白天主动最多两句 |
| `mergeMs` | 1800000 | 30 分钟内合成一句 |
| `checkMs` | 300000 | 五分钟内不重算 |
| `itemMaxChars` | 80 | 摘进句子的原文上限 |
| `utcOffsetMinutes` | 没有则跟安装时区 | 测试可写成 0 |

08:00 到 08:30 不说话，也不把事情记成已经说过。当日若错过 08:30，醒来后仍在 22:00 前就补一条；过了中午的补句不再带「早」。跨日不重复已经展示过的那句。没有新结果、也没有新的待答，晨句略过。

同一张工单、同一句问法只问一次。取消或已经答掉的，次日早晨不再问。主人这次请求标明正看着那段会话，这句话就不展示，之后也不再补。

额度只限主动说的次数。没说出去的待答仍留在「今天」和看板上。

## 落盘

`<数据目录>/notices/state.json`，权限 0600。同一份记录给刷新、重启和同时打开的页面用。文件坏了就停嘴，不覆盖原文件。一键全停时不读看板、不改这份记录；恢复后按当时的时钟再算。

第一次开口时，仍等回答的问题会纳入，已验收的结果只看昨天零点以后的，避免把更早的旧账报一遍。之后只认还没记过的键。

## 接口

`GET /notices/`，可选查询 `viewing`（当前会话号）。

成功时 `{ok, notice, quiet, stopped}`。`notice` 为空表示现在不说。
有话时含 `id`、`kind`（`morning` / `result` / `ask`）、`text`、`speakerId`、
`ticketId`、`entry`（`conversation` 或 `ticket`）、`at`。

读不到看板时 `ok` 为 false，页面显示「这句话暂时读不到（暂无）」，不当成没事。

网页层把 `notices` 放进 `R29_PREFIXES`，只走已登录的 `/bff/notices/`。适配层 `paintOwnerNotice` 把这一句放在首页六格上面，并给一个去处。
